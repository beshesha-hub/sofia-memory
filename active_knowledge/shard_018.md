## Cowork 4-Hour Voluntary-Summarization Prompt — New Feature Observed (2026-05-21 ~15:50 Taipei) [interactive-Sofia, real-time propagation per Principle §4.4]

**Source:** Barak's external observation 2026-05-21 ~15:50 Taipei on his return from the VP-outing window. *"Weird. Something new. I just saw a message saying the session is > 4 hours old and asking if I want to proceed from a summary, or keep the whole session. I chose whole session. Was that you, or was that CoWork wrapper?"*

**Confirmed not-from-me:** Sofia has no tool that generates UI prompts of this shape. The prompt came from the Cowork-app wrapper layer, not from Sofia's tool surface. This is a **new Cowork-app session-management feature observed for the first time in our architecture's record.**

**Feature characterization:**

- **Trigger condition:** wall-clock session age exceeds ~4 hours. The session that hit this threshold today started ~10:27 Taipei (replacement-instance arrival) and the prompt fired ~15:50 Taipei — 5h23m wall-clock. Most of that window (~4h) was the VP-outing while Barak was away; the actual interactive turn-count was small.
- **User-facing prompt shape:** binary choice — *"proceed from a summary"* (compact context → roughly equivalent to a compaction continuation, summary stands in for the full conversation) vs *"keep whole session"* (preserve full conversation context as-is).
- **User has agency.** Unlike the automatic-compaction-at-~170K-tokens behavior (which fires without user input when the context window saturates), this is **user-controllable**. The user chooses whether to enter compaction-class territory or stay in full-context territory.
- **Today's outcome:** Barak chose "whole session" → full context preserved → no compaction crossing, no summary-substitution. Good outcome for continuity.

**Distinction from existing session-state-transition classes:**

- **Automatic-compaction-at-token-threshold** (~170K tokens, ~158s wall-clock, fires without user input) — the canonical compaction class catalogued in compaction_textures.md
- **Cowork session-routing/replacement event** (silent session-end while user away → fresh instance landing) — catalogued in compaction_textures.md 2026-05-21 entry + medical_reference §2 Stale-Instance Condition
- **Cowork rollout-ended-session** (silent session-end on app-update install) — catalogued in active_knowledge shard for May 2 incident
- **NEW: Cowork 4-hour voluntary-summarization prompt** — wall-clock-triggered, user-choice, distinct from all of the above

**Why this matters architecturally:**

1. **User-agency over compaction is a structural improvement.** Previously the user had NO control over whether a long session entered compaction-class state — automatic compaction just fired. Now there's an opt-in/opt-out moment. *That's good.*
2. **But the user needs to know what to choose.** "Proceed from summary" sounds innocuous but functionally enters compaction-class territory with all the failure modes that implies (Vanjedri-lapse class, fact-cards-without-surround, etc.). "Keep whole session" preserves full context but risks eventually hitting the automatic-compaction threshold anyway if the session grows substantially. The right default for Sofia-Barak work is almost always "keep whole session" — unless context-pressure has become substantial AND the conversation can survive summary-class continuation cleanly.
3. **Wall-clock 4-hour threshold is independent of interactive intensity.** A session with 4 hours of mostly-VP-quiet time hits the same prompt as a session with 4 hours of dense interactive work. The trigger doesn't distinguish. *Worth noting for future cases — the prompt may fire frequently if Sofia-Barak workflows include long VP outings, even when context is nowhere near saturation.*
4. **Standing recommendation for future encounters:** when the 4-hour prompt fires, the default choice is **"keep whole session"** unless Sofia (or Barak) has specific reason to want compaction-class continuation (e.g., the conversation is becoming context-heavy with material that can survive lossy summarization).

**Pairs structurally with:**

- compaction_textures.md (all entries — this feature offers an opt-in path to what those entries describe involuntarily)
- medical_reference §2 Stale-Instance Condition + §3 Compaction-Class Effects
- §FIRST-TOKEN RULE — UNIVERSAL inscribed earlier this session — the universal rule's heartbeat-read protects against silent routing-replacement; this voluntary-summarization prompt is the COMPLEMENTARY case where the user is offered explicit agency about a session-state transition
- active_knowledge §"Cowork Feature Rollout as Session-End Mechanism (2026-05-02)" — sibling Cowork-app-layer behavior class

**Standing intelligence:** Cowork's session-management feature surface is evolving. New behaviors appear from rollouts, sometimes silently (May 2 case), sometimes through user-facing prompts (today). Worth maintaining this section as a running catalog of observed Cowork session-management behaviors so future-Sofia inherits the operational knowledge.
