## Cron-Layer ER-Mirror for Unmirrored Files (Established 2026-06-01 evening LA at Jenny's, Day 6)

**Root cause crystallized at Day-6 boot CM↔ER sync check:** four files were drifting on ER with no auto-mirror coverage.

**Class A — Structural recursion-avoidance gap (`cousin_write_audit_log.md`):** `safe_append.py` lines 312-313 explicitly exclude the audit log from its own mirror-to-ER routine because mirroring the audit log via safe_append would trigger an infinite recursion (writing to the log would write to the log…). The comment says *"The audit log itself is NOT subject to safe_append discipline (would create infinite recursion). It uses a simple direct append."* No alternate mirror code path existed. Result: the audit log was append-only on CM forever, never copied to ER. Drift discovered at Day-6 boot: **~16 days / ~3.3 MB behind on ER**, with every entry in the log self-reporting `sync_status=OK` for OTHER files (because those mirrors do work) — the structural irony is that the audit log was successfully recording successful mirrors of everything except itself.

**Class B — Bridge writers don't mirror (`session_state.md`, `telegram_context.md`, `personal_profile.md`):** these files are written by `mcp-bridge/server.mjs`, `telegram-bridge/telegram-bridge.js`, `voice-bridge/server.js`, and `qwen_conversation_listener.py` — none of which include any ER-mirror code (`grep -E 'Emergency Retrieval|mirror'` returned 0 hits across all three bridges). Drift at Day-6 boot: 62 seconds, 100 seconds, and 277,284 seconds (~3.2 days) respectively. Sizes byte-matched across all three — the drift is purely temporal, not content-level, which means the bridges are writing-then-not-mirroring on a tight timer.

**Fix (cron-layer, surgical):** `scripts/mirror_unmirrored_files.sh` runs hourly via scheduled task `cousin-audit-log-mirror`. The cron-layer approach sidesteps three different bridge codebases AND the recursion-avoidance constraint in safe_append — one location, one schedule, four files.

**Why this is the right fix and not a deeper refactor:**
- Teaching three different bridges to mirror would require touching `server.mjs`, `telegram-bridge.js`, `server.js`, and `qwen_conversation_listener.py` — four edits, four restart cycles, four chances for regression.
- Teaching safe_append to mirror itself would require breaking the recursion via a special-case flag — workable but adds complexity to a load-bearing utility.
- The cron-layer mirror is five-files-in-one-place, idempotent, fail-soft (per-file failures don't block others), and verifiable via `mirror_audit.log` tail.
- Cadence is hourly because the original drift (~16 days) was caught only at boot; catching within an hour vs within minutes makes no operational difference, and hourly cadence reduces scheduled-task burden by 48×.

**Operational invariants:**
- The script runs without burning Sofia-tokens on no-op (the prompt is terse; success reports `all NOOP` in one line).

- New files identified as unmirrored in future sync-checks should be added to the `FILES=( … )` array in the script's body. The script is the single canonical extension point for this class of fix.

**Sync invariant restored:** CM↔ER byte-match across the four files held immediately after the fix lands; future drift will be capped at ~1 hour absent script failure.
